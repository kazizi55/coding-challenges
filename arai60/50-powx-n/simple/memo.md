### Step 1

base caseはx自体を返すで良さそう。nが1の時かな。nがマイナスの時も考えられるのでreturnするときに分岐して返すのがいいかな。うーん、もうちょいで解けそうなんだけど、どうやってネストした値を掛け合わせていくのかがわからないなー。フィボナッチみたくやるとTLEになってしまった。答えを見る。

なるほどー、指数法則を使うのかー。(a^b)^c == a^b^c。バイナリ法ともいうらしい。底xを2乗する代わりに、指数nを半分にすれば、log n回で解けるというわけかー。

>         if n % 2 == 1:

            return x * self.myPow(x, n - 1)

ここ、次のiterationでn//2されたときに1少なくなることを見越してこの段階でxをかけているのかー。若干わかりづらいなー。

Solution1,2をみてみて、奇数パートが回収 (実際の数字を掛ける)、偶数パートが加速、とみるとわかりやすいなーと思った。

### Step 3

#### Solution 1

再帰で解きつつ、結果を後から2乗している解法。奇数の時も2乗して返せるので同じO(log n)でも若干こちらの方が時間計算量は少ない。
ただどうしても入力を破壊しているのが好きではないんだよなー。プリミティブだから外部の値を書き換えないローカルスコープなのはわかるが、それでも一つの関数内でnとxが指す意味が変わるのがわかりづらいのではと思う。

一方で処理が一番追いやすいのはこれ。底が不変だからだと思う。

#### Solution 2

whileを使いつつ、nを2の階乗値で削っていく解法。
最後のif n > 0で余ったnを階乗値としてかけているのが辻褄合わせしているみたいだなという感じ。
Solution 1と同じく入力を破壊しているのが気になる。
